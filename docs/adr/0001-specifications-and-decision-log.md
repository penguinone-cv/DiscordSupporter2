# ADR-0001: 仕様の正本と設計判断履歴を分離する

- 日付: 2026-09-12
- 状態: Accepted
- 対応する正本: [文書運用](../README.md)

## 背景

仕様がREADMEとテストへ分散し、細かいテストが仕様の代替になっている。利用者からADRによる整理と、正本・ログの保存場所の分離が求められた。

## 判断

`docs/spec/` を現在の仕様の正本、`docs/adr/` を背景・判断・影響を残すADRの集合（ADL）とする。READMEは導入案内と正本への入口にする。正本は現行の内容へ更新し、判断変更は連番ADRを追加して前後をリンクする。

形式は [Architecture Decision Record](https://github.com/architecture-decision-record/architecture-decision-record) の考え方に基づく。ディレクトリ分離と更新手順は本プロジェクトの選択であり、参考資料がこの配置を義務づけているという意味ではない。

## 代替案

- ADRだけに仕様を置く: 現在の有効仕様を履歴から再構成する必要があり、参照が難しい。
- READMEだけを更新する: 背景・却下理由が消えやすい。
- ADRと正本に同じ仕様全文を置く: 二重更新による不整合が生じる。

## 影響

現在の契約と判断経緯を別々に読める。仕様変更では両者の整合確認が必要になるが、全修正でADR作成を強制しない。初回は実装を確認して基準化し、別ブランチの未反映機能を採用済みにしない。
