# ADR-0006: 募集判定providerと検証済み判定例を分離する

- 日付: 2026-09-19
- 状態: Accepted
- 対応する正本: ../spec/application.md APP-02

## 背景

募集判定はOpenAIに依存し、CSV全件を「類似すれば必ず同じラベル」の指示と共に渡していた。CSVの検証と評価データの分離がなく、例の増加や矛盾による誤通知を検知しにくい。Jevは文章の生成ではなく型付きの判断を返すため、理由生成を前提とした連携を分離する必要がある。

## 判断

募集判定のみconfigでOpenAI / Jevを選択し、未指定はOpenAI。共通の意図ベースの基準・参考例を、それぞれのAPI形式で渡す。Jevはyes/noに適したNoulを利用し、確率のしきい値をconfigで管理する。理由は常に空文字で、別モデルによる理由の補完は行わない。日付抽出は引き続きOpenAIを使う。

判定例は少数の検証済みfew-shotとして扱う。件数・サイズ・ラベル・重複・矛盾を検証し、保存と実行中の反映は正常なデータだけに限定する。運用ログと人手の正解ラベルを区別する。API失敗を通常の非募集ログへ混ぜない。評価データは例から分離し、devとtestを用意する。

## 代替案

- 全件挿入を無制限に続ける案: 費用・入力長・矛盾の管理ができない。
- ベクトルDBによる検索: 現在11件で必要性がなく、検索精度や別API依存が増える。規模と評価結果を見て再検討する。
- Jev障害時のOpenAI自動切替: 運用者が選んだproviderと費用・判定挙動を一致させるため採用しない。

## 影響

既存CSV列とWebUI編集を維持する。上限超過や矛盾するCSVは修正が必要になる。モデルやしきい値の変更には評価が必要で、合成の少数例だけで本番精度は保証できない。OpenAIキーは日付抽出のため引き続き必要。

Dockerの単一ファイルbind mountではrenameによる置換ができないため、Composeの標準CSVはdataディレクトリへ初回コピーして編集する。旧ファイルは読み取り専用の移行元として残し、移行済みファイルは上書きしない。独自csvPathは自動変更せず、運用者がディレクトリマウント配下を指定する。

初回評価でNoul 0.5では引用のみの発言に誤通知が発生し、devの確率分布を基に既定値を0.8へ調整した。独立したtestで追加評価した結果と制約は [評価記録](../../evals/recruitment/results-2026-09-19.md) を参照する。
