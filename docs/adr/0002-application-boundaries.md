# ADR-0002: 現行アプリケーション境界と保存方式を基準化する

- 日付: 2026-09-12
- 状態: Superseded by [ADR-0005](0005-main-activity-baseline.md)（旧基点65bdf0eの記録）
- 対応する正本: [APP-01〜03・06](../spec/application.md)

## 背景

Bot、ゲーム管理、募集検出、予定、WebUIが共存し、SQLiteとJSON・CSVを使い分けている。テストを整理するには保存制約や外部副作用を理解し、単純な関数単位のテストと区別する必要がある。

## 判断

今回の整理では現行の単一Node.jsプロセス、Discord入口→サービス→repositoryという構成を維持する。ゲーム・予定・募集の整合性はSQLiteで扱い、リマインド・カレンダー・参考データは既存保存方式を維持する。ソフトアーカイブと復帰希望の管理者確認を守る。認証や保存先を統一する変更をこの整理に混ぜない。

## 代替案

- 全データをSQLiteへ移行: 将来の選択肢だが、既存JSONの移行と障害処理を別途設計する必要がある。
- WebUIを別サービス化: 分離の価値はあるが、現在のテスト削減に必要な変更ではない。

## 影響

動作を変えずに仕様とテストの責務を整理できる。保存方式を跨ぐ処理の完全な原子性は得られない。WebUIのアクセス制御や投票の再起動復元にも現行の限界が残る。DB一意制約・復旧・誤通知防止のテストは、低価値な実装追従テストとして削除しない。
