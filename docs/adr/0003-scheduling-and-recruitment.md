# ADR-0003: 現行の予定・募集契約を基準化する

- 日付: 2026-09-12
- 状態: Accepted（現状の記録。過去の採用理由の復元ではない）
- 対応する正本: [APP-04・05](../spec/application.md)

## 背景

予定の基本値補完、候補集計、画面表示、募集確定は異なる責務を持つ。今回のチェックアウトでは、集計はJSTの当日以降、表示・募集は月のタイムゾーンで開始時刻が未来の先頭10件という制約がある。これらを一つの「未来判定」と考えると必要なテストまで重複扱いしてしまう。

## 判断

現在のDiscordパネル、時間枠、二段階の候補フィルタを仕様へ明記し、今回の変更で統一しない。一般メンバーの募集操作を維持する。参加者または所定の管理権限者による一度だけの確定、既存リマインドへの直接登録、参加状態の競合処理を独立した重要契約として扱う。

## 代替案

- 予定画面・日付判定を新しい方式へ置換: 機能変更になるため別ADRと実装の対象。
- サービステストだけを残してrepository・入口のテストを全削除: DB一意性、Discord応答、本人限定表示など別の故障を検出できなくなる。

## 影響

既存のユーザー動作と回帰検証を保持できる。一方で、JST集計と月タイムゾーン、返信リマインドのホスト時刻という差は残る。タイムゾーンや開始時刻を変更する際は対象経路を明示して判断し直す。
