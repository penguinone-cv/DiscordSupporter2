# ADR-0004: リスクに応じて必要なテストを残す

- 日付: 2026-09-12
- 状態: Accepted
- 対応する正本: [テスト方針](../spec/testing.md)

## 背景

全変更でRed-Green-Refactorを求める開発ルールがあり、内部代入やログ装飾のテストも蓄積している。利用者から必要な単体テストのみを残すよう依頼された。基点 `65bdf0e` は28ファイル・182ケースが成功した。

## 判断

TDDは手段として任意に使い、テストの追加・維持は守る契約と障害リスクで判断する。件数削減そのものを目標にしない。全28ファイルを棚卸しし、削除・統合するのは下表の範囲とする。残るファイルの責務は正本の対応表へ集約する。

| 対象 | 整理 | 理由・代替保証 |
| --- | --- | --- |
| `tests/utils/logger.test.js` | 7ケースを削除 | console転送・プレフィックス・日時装飾・DEBUG切替は専用単体テストの対象外とする。ログ変更時の運用確認で扱う。自動検証が残るとは主張しない |
| `tests/config/configLoader.test.js` | getterの4ケースを1ケースに統合（3減） | falsy値・欠損パス・未ロードを代表契約として残す。必須設定の正常／異常6ケースは保持 |
| `tests/services/roleManager.test.js` | 初期化2ケース・判定ヘルパー3ケースを削除（5減） | カスタムカテゴリは実際の付与成功、既定値は通常の付与フロー、対象外カテゴリと親なしは付与しない結果で検証する。作成・重複付与防止・API失敗は保持 |
| `tests/utils/csvLoader.test.js` | 6ケースを3ケースに整理（3減） | parserのモックを除去し実CSVから分類まで検証。引用符・カンマ・空行、欠損ファイル、不正CSVを保持。空コンテキストの見出しや募集だけの重複表示ケースは削除 |
| `tests/commands/vote.test.js` | 件数を維持し自作Discord builderモックを削除 | 実builderで結果の3人・2/2/1票を確認する。従来の「editが呼ばれた」だけでは集計誤りを検出できない。タイマーはfake timerで後始末する |
| その他23ファイル | 保持 | 所属・権限、日付、保存、Discord制約、配送、失敗補償などの契約を担う。サービスとrepositoryで同じ操作名でも検証する故障が違う |

整理後は27ファイル・164ケース（18ケース減）。`npm test -- --reporter=dot --silent` ですべて成功を確認した。単体／結合テストの配置や `npm test` の対象範囲を狭めて見かけ上減らすことはしない。

## 代替案

- 一律に半減する: 重要な回帰・データ整合性の保証を失う。
- parameterized testへの置換だけで整理する: 記述は短くなるが、不要な検証の選別にならない。
- 何も削除せずTDDを続ける: ログ装飾や内部表現の変更にまで保守負担が残る。

## 影響

低価値な検証と大きな自作モックが減る。残すテストは仕様へ対応づけ、追加時も同じ基準で判断できる。すべての仕様を自動検証しているわけではなく、外部連携・管理権限の一部・WebUIは別の確認を要する。検証は変更前後の全テストと差分確認で行い、実Discordへの操作は今回の整理に含めない。
