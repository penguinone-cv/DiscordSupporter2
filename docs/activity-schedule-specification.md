# Discord Activity 月間予定カレンダー仕様書

## 1. 目的

Discord Supporter の月間予定編集を、週送りと日付プルダウン中心の操作から、月全体を見渡して直接操作できる Discord Activity へ置き換える。

利用者は Discord を離れず、現在所属している同一サーバーの全非 Bot メンバーの予定を確認できる。予定の編集と基本予定への復元は、認証された本人のデータだけを対象とする。

## 2. 対象範囲

- Activity ページ: `https://www.penguinone.net/discord/schedule/`
- Activity API: `https://www.penguinone.net/discord/api/activity/schedule/*`
- 対象月: ギルド設定のタイムゾーンで判定した今月と翌月
- 既定タイムゾーン: `Asia/Tokyo`
- 既存のリマインド閲覧ページ `/discord/calendar` は別機能として維持する
- 既存の Discord 週表示は障害時のフォールバックとして維持する

## 3. 対象外

- 前月以前の表示・編集
- 月をまたぐ範囲選択
- 飛び飛びの日付の一括選択
- 管理者による他メンバーの予定編集
- 通常ブラウザーからの予定閲覧・編集
- DM、グループ DM での利用
- 予定変更の Discord チャンネル通知
- 範囲復元の取り消し
- 複数サーバーの予定の横断表示

## 4. 利用者と権限

### 4.1 閲覧

- Discord OAuth で認証済みで、対象サーバーに現在所属する非 Bot メンバーだけが利用できる。
- 利用者は、同じサーバーに現在所属する全非 Bot メンバーの対象月の予定を閲覧できる。
- 退会者は表示・集計・アクセス対象から外す。
- 退会者の保存済みデータは削除せず、同じ Discord ユーザー ID で再参加した場合に再び利用する。
- 他サーバーの予定は取得できない。

### 4.2 編集

- 単一予定枠の変更と範囲復元は、OAuth セッションで確定した本人の予定だけに許可する。
- 管理者にも他人の予定編集権限を付与しない。
- API リクエスト本文や URL に含まれる `userId`、`guildId` を認可根拠にしない。
- 対象月、日付、予定枠が認証済みサーバーに属することをサーバー側で検証する。

## 5. 起動と認証

### 5.1 主導線

- 既存メンバーパネルの「月間予定を編集」から Activity を起動する。
- 起動元の Discord サーバーを表示対象として固定する。
- App Launcher からサーバー情報なしで起動された場合は、対象サーバーのメンバーパネルから開くよう案内する。

### 5.2 Activity 外の表示

- `/discord/schedule/` を通常ブラウザーで直接開いた場合は、予定データを返さず「Discord から起動してください」と表示する。
- 既存 WebUI の無認証 API と Activity API を分離する。
- Discord の認可コードはサーバーでアクセストークンへ交換し、クライアントシークレットをブラウザーへ渡さない。
- 認証後は短時間有効な Activity セッションを発行し、全 API で検証する。
- セッション発行前にDiscordのActivity Instance APIでアプリケーション、起動ギルド、OAuth本人の参加を検証する。APIごとに署名と現在の非Bot所属を検証する。

## 6. カレンダー表示

### 6.1 共通

- 日曜始まりの 7 列カレンダーとする。
- 月外の日付はパディング表示し、選択・編集はできない。
- 今月内の過去日も表示・編集できる。
- 日付、曜日、今日、月境界、祝日はギルドのタイムゾーンで判定する。
- 日本の祝日は休日用予定枠を使用する。
- 平日は夜、土日祝は昼と夜の予定枠を使用する。互換用の保存時刻は画面とActivity APIへ表示しない。
- 状態は `○ 参加可能`、`△ 未定`、`× 参加不可`、`― 未入力` の記号と文言で示し、色だけに依存しない。

### 6.2 月間セル

- 各予定枠について `○`、`△`、`×`、`未` の人数を表示する。
- `未` は「未入力」と「未登録」の合計とする。
- 各予定枠で `○ + △ + × + 未` が、表示時点の全非 Bot メンバー数と一致する。
- 狭い画面では日付と状態記号・人数を優先し、メンバー名はセル内に表示しない。

### 6.3 日付詳細

- 日付セルを選択すると、その日の予定枠ごとのメンバー一覧を表示する。
- 一覧では `参加可能`、`未定`、`参加不可`、`未入力`、`未登録` を区別する。
- 表示名は現在のサーバーニックネームを使用する。
- 本人を先頭に表示し、他メンバーは表示名順とする。
- 本人の行だけ状態変更操作を表示する。
- 他メンバーには状態と表示名だけを表示し、基本予定由来か手動設定かは表示しない。

## 7. 未入力と未登録

- `未登録` は、対象月に月間予定が 1 件もなく、その月のどの予定枠にも適用できる基本予定がないメンバーを指す。判定単位は「メンバー × 対象月」とする。
- 基本予定だけを登録しているメンバーは登録済みとする。
- 一部の曜日または予定枠だけを登録しているメンバーは登録済みとし、状態がない予定枠を `未入力` とする。
- 月間予定で `unset` を明示保存した予定枠は `未入力` とする。
- 前月に入力があっても、対象月に月間予定と適用可能な基本予定がなければ対象月では `未登録` とする。

## 8. 予定編集

- 本人は予定枠ごとに `○ / △ / × / 未入力` を直接指定する。
- 従来の押下回数による循環変更は Activity では使用しない。
- 選択のたびに即時保存し、`保存中`、`保存済み`、`保存失敗` を表示する。
- 同じ状態を再指定しても結果が変わらない冪等な更新とする。
- 同一ユーザーが複数端末で単一枠を更新した場合は後勝ちとする。
- 全体の保存ボタンは設けない。

## 9. 選択範囲を基本予定へ戻す

- 本人が「範囲選択」モードを開始し、開始日と終了日をタップして連続範囲を指定する。
- 開始日と終了日の両方を対象に含める。
- 選択範囲は同一表示月内に限定する。
- スマートフォンのスクロール操作と競合するため、ドラッグ選択は使用しない。
- 実行前に対象期間と、昼・夜を含む対象予定枠を確認画面へ表示する。
- 確定時点の基本予定を範囲内の全予定枠へ 1 トランザクションで適用する。
- 基本予定がない予定枠は `未入力` に戻す。
- 表示後に本人の対象範囲が別端末で更新されていた場合は、競合を表示して最新状態での再確認を求める。

## 10. 共有表示の更新

- 自分の保存結果は応答後すぐ表示へ反映する。
- 他メンバーの変更は、Activity を開いている間に数秒以内を目標として自動反映する。
- 自動更新は5秒間隔のHTTP取得とし、非表示・PIP/Grid・保存中は停止する。保存後は新しい読み取りで確定状態を表示する。
- 手動更新操作を用意する。
- Activity が Focused 表示へ戻ったときは月全体を再取得する。
- 永続データの共有単位は Activity インスタンスではなく Discord サーバー ID とする。

## 11. レスポンシブ・アクセシビリティ

- デスクトップ、Discord Web、iOS、Androidを対象とする。
- スマートフォンでも 7 列カレンダーを維持する。
- スマートフォンの日付詳細と編集は下部シートで縦に表示する。
- Discord Safe Area と OS の Safe Area を考慮し、ノッチ、ホームインジケーター、Android 戻る領域へ操作部品を重ねない。
- タップ対象は原則 44px 以上とする。
- キーボード操作、フォーカス表示、ARIA grid、ダイアログの Escape 閉じ、保存状態の live region に対応する。
- Focused レイアウトで編集を提供し、PIP/Grid では簡易な読み取り表示と全画面表示案内だけを出す。

## 12. エラー処理

- 認証失敗、所属確認失敗、期限切れセッションでは予定データを返さない。
- 保存失敗時は直前の確定表示へ戻し、再試行手段を示す。
- 最新データ取得に失敗している状態で範囲復元を実行させない。
- サーバーメンバー一覧を完全に取得できない場合、不完全な人数集計を表示せずエラーと再試行を示す。
- 無効な月、日付、予定枠、別ギルドの識別子は拒否する。

## 13. データ互換性

- 既存の `availability_months`、`availability_slots`、`user_availability_patterns`、`user_availability` を予定データの正本として再利用する。
- 基本予定は既存月を自動上書きせず、範囲復元を実行した場合だけ再適用する。
- 明示的な `unset` を削除扱いにしない。
- 予定データのための新規 DB マイグレーションは原則不要とする。
- 認証セッションは予定テーブルと分離する。

## 14. 受け入れ条件

1. 認証済みメンバーが Discord 内で `/discord/schedule/` の Activity を開ける。
2. 日曜始まりの今月・翌月カレンダーがデスクトップとスマートフォンで利用できる。
3. 今月内の過去日を含む全日付を直接選択できる。
4. 各予定枠の人数合計が現在の全非 Bot メンバー数と一致する。
5. 日付詳細で未入力と未登録を区別し、全メンバーの名前と状態を確認できる。
6. 認証本人だけが自分の状態を直接指定でき、他人の更新は拒否される。
7. 同月内の連続範囲を確認後に基本予定へ原子的に戻せる。
8. 退会者と Bot は表示・集計されず、再参加者の既存データは復元される。
9. Activity 外の通常ブラウザーや別ギルドから予定を取得できない。
10. 他メンバーの変更が自動更新または手動更新で反映される。
11. 既存の基本予定、候補日程、リマインドカレンダー、週表示が壊れない。
