## 1. 仕様適合

| 仕様 | 実装結果 |
| --- | --- |
| 予定画面から固定時刻を除く | 基本予定・月間日別詳細を `昼/夜：状態` 表示へ変更 |
| 候補を日付＋区分で表示 | 候補本文・選択肢を `日付 昼/夜` 表示へ変更 |
| 募集投稿から開催時刻を除く | Embedを `開催日`＋`時間枠` 表示へ変更 |
| 当日を終日募集可能にする | 月間予定のタイムゾーンによる日付比較へ変更 |
| リマインド本文から固定時刻を除く | 日付＋`昼/夜`だけを保存し、通知時刻12:00は維持 |
| 昼夜と既存データを維持 | DB列・slot ID・sort order・保存済みデータは変更なし |

候補画面、公開パネル、利用者向けエラーは `候補日程` に統一した。内部のcustom IDとDB構造は変更していない。

## 2. 正確性・堅牢性

- `YYYY-MM-DD` の日付キーを月間予定のIANAタイムゾーンで比較し、当日を含み前日を除外する。
- JST以外の `America/New_York` 境界も実DBテストで確認した。
- 同じ休日の候補は実データで昼、夜の順になることを確認した。
- 上位10件は日付対象を絞り込んだ後、既存集計順の先頭10件を使用する。
- 候補選択は表示位置ではなくslot IDで維持される。
- 不正候補、前日候補、上位10件外、重複募集の既存拒否動作を維持する。
- 参加・不参加、確定権限、重複リマインド防止のロジックは変更していない。

## 3. データ・互換性

- SQLiteマイグレーションなし。
- `start_minutes` / `end_minutes` と既存の14時・21時値は互換用に保持する。
- 値は予定表示、候補可否、募集可否、リマインド本文に使用しない。
- デプロイ前の募集メッセージと保存済みリマインドの一括更新は行わない。

## 7. 合意済みの制約

開催日当日の12:00より後に確定した場合、過去時刻のリマインドは送信されず、確定直後のロールメンションだけが送られる。この挙動は確定仕様どおり変更していない。

依存導入時にnpmが報告した既存依存の脆弱性は、今回の機能範囲外として自動修正していない。
