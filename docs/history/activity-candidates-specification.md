# 候補日確認 Activity 仕様書

## 合意した仕様
- 最新 main f4821f7 を基点とし、既存 Activity 内で「予定入力／候補日確認」を切り替える。初期画面は予定入力。
- 共通入口は「予定・候補日を開く」。従来の候補確認は代替として残す。
- ゲームは初期未選択。稼働中かつチャンネル設定済みゲームから選び、今月・翌月のカレンダーを表示する。
- 月のタイムゾーンで今日以降、○または△が1人以上の昼／夜枠を日付順で全件表示する。
- ゲーム希望者で現サーバーに所属する非Botの○△×人数と、日付詳細で名前・回答を表示する。未回答者は詳細に追加しない。
- 名前の表示によりゲーム希望者が分かることをメンバーパネルの案内にも明記する。
- 基本予定と手動回答の優先関係は既存集計を利用する。
- 日付詳細でゲーム、日付、昼／夜、投稿先を示し、明示的な募集ボタンで既存ゲーム募集を投稿する。
- 一般メンバーも募集可能。サービスの10件制限を撤去し、従来画面の表示10件は維持する。
- 募集済みは状態を表示して再投稿不可。送信直前の再集計、DBの重複防止を利用する。通信失敗時は自動再送せず再取得する。
- 参加表明・開催確定・リマインドは既存Discord募集メッセージで行う。
- 表示中は5秒更新と手動更新。非表示・縮小時は更新停止。古い応答を切替後に適用しない。

## API
既存認証済み /api/activity/schedule 配下に追加する。
- GET /candidate-games: games [{id, displayName, channelId}]
- GET /candidates?offset=0|1&gameId=ID: month, today, game, candidates。候補は slotId, localDate, label, 各人数, members [{userId, displayName, status}], recruitment {id,status,messageId,channelId} または null。
- POST /recruitments: body {monthId,gameId,slotId}。セッションからguildとuserを確定。結果 {recruitmentId,channelId,messageId}。
- 不正入力400、所属認証401/403、対象なし404、競合・候補変更409、予期しない失敗503。内部情報は返さない。
- 対象月は今月・翌月のみ。別サーバーの月・ゲーム・枠を拒否する。

## 対象外
DB変更、新規Discordアプリ、OAuthスコープ追加、候補画面からの予定編集、前月閲覧、Activity内の参加表明・開催確定。

## 受入条件
11件目以降も募集でき、詳細の名前と集計人数が一致する。二重投稿しない。予定入力と従来画面が回帰しない。全テスト・Activityビルドに成功し、Discord実機確認の実施有無を記録する。
