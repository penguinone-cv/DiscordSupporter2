# 仕様と設計判断

## 保存先

| 場所 | 役割 | 更新方法 |
| --- | --- | --- |
| [spec/application.md](spec/application.md) | 現在のアプリケーション仕様の正本 | 現行仕様へ更新する |
| [spec/testing.md](spec/testing.md) | テストの採否・検証方針の正本 | 現行方針へ更新する |
| [adr/](adr/README.md) | ADR本文と索引。判断の背景・選択・影響を記録する履歴（ADL） | 判断ごとに連番ファイルを追加する |

READMEは導入・運用の案内です。現在の仕様は `spec/`、なぜそう決めたかは `adr/` を参照します。ADRを現在仕様のコピーとして重複管理しません。実行時のCSVログや `data/` はこの判断履歴とは別物です。

初回整理は2026-09-12、基点は `65bdf0e` です。このチェックアウトの実装を確認して文書化しました。過去の別ブランチにある機能や希望は、実装済み仕様として持ち込みません。

## 変更時

1. 影響する仕様項目と利用者の振る舞いを確認する。
2. 権限、永続化、外部連携、重要な制約を変える場合はADRを追加する。単純な文言変更や通常のバグ修正にはADRを強制しない。
3. 仕様変更・実装・必要な検証を同じ変更に含める。既存テストで守れるなら増やさない。
4. 採用後は正本とADR索引を更新する。判断を変更するときは旧ADRを Superseded にし、後継ADRへのリンクを記す。過去の背景・判断を現在の説明に書き換えない。

参考: [Architecture Decision Record](https://github.com/architecture-decision-record/architecture-decision-record)。ADRは重要な判断と背景・影響を記録し、その集合がADLです。正本と履歴のディレクトリ分離は本プロジェクトで採用した運用です。
